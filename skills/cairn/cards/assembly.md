# The assembly card

Selected by asm. Codes: E-ASM-CLOBBER E-ASM-CONSTRAINT E-ASM-EFFECT E-ASM-LANE E-ASM-OPERANDS E-ASM-TARGET.

```text
asm x86_64 "bswapq %0" (out r:u64 = x); is typed assembly, inside unsafe { }. The target is ptx with the architecture it needs (asm ptx sm_75 ...), run only in a kernel fn or a lane of a region that indexes an @device view, or x86_64 or aarch64, run only in host code and built only on a host of that family (E-ASM-TARGET). Operands are numbered as written, outputs first, and the template names every one as %0, %1, with %% a literal % (E-ASM-OPERANDS). The type decides the register: host integers r, host floats x or w; PTX u16/i16 h, u32/i32 r, u64/i64/usize l, f32 f, f64 d; bool, storage floats, records and PTX u8 have none (E-ASM-CONSTRAINT). out name:T binds a fresh local after the statement, out name:T = e starts it at e. A view or local array input passes its address and needs effects(read:xs) or effects(write:xs), which lends it like a call (E-ASM-EFFECT); effects may also name fence barrier atomic io mmio, trusted as written, and any of them makes it volatile with a memory clobber. clobbers(rax, rdx) names host registers written besides the outputs (E-ASM-CLOBBER); asm volatile keeps a clock read from being merged. The row gets asm:TARGET and the declared effects, so bind each call to a let (E-EFFECT-ORDER). In device code PTX declares only reads, writes and fence (E-ASM-LANE), and an address is a whole-array access for the lane rule (E-PARALLEL-RACE).
```
