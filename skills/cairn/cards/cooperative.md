# The cooperative card

Selected by barrier pipeline shuffle shuffle_down shuffle_up shuffle_xor warp warp_all warp_any warp_ballot warp_match.
```text
blocks b in g threads t in 256 { ... } runs g blocks of 256 threads, b and t usize; up to three names a side, fastest first (blocks bx, by in gx, gy threads tx, ty in 32, 8: thread tx + 32 * ty). Thread extents are literals or constants, whole warps, 32 to 1024 in all (E-COOP-SHAPE). shared tile:f32[1056] = zeroed; declares directly in the body one array per block, zeroed where each block starts, 48 KiB in all (E-COOP-SHARED); shared warps:f32[8]; is not zeroed, and every element a thread reads (or updates atomically) must be written first, by it or by any thread before a barrier, on every path (E-COOP-UNWRITTEN). barrier; waits for every thread of the block: never under a condition on a thread name, nor in a loop with break or continue (E-COOP-BARRIER). A local assigned from t, lent rw to a call, written through an element or assigned by a closure differs between threads, as does what an atomic or typed asm returns, and the right side of && or || runs only where the left lets it. Runs on the device when a view it indexes is @device, else on host threads; its row gains par:device or par:host and zero_init. blocks b in g threads t in 256 { ... } then threads t in 256 { ... } adds a finish: one block of the region's thread count (E-COOP-SHAPE), run once after every block has finished, even for g = 0, that may read anything the blocks wrote, plainly or atomically; no block name or block local is in scope, and it declares its own shared arrays; on the device it is still one launch. A feature devices.md's table of what fast kernels use marks foreign (dynamic shared memory past 48 KiB, warp match, clusters, TMA, wgmma, grid-wide sync, graphs) is written as a foreign CUDA implementation of the CAIRN reference, which cairn foreign inspects and cairn validate holds to it; never settle for a narrower kernel.

Between two barriers no two threads touch one element of a shared array where either writes: two writes E-COOP-CONFLICT, a read of what another thread wrote earlier in the phase E-COOP-UNORDERED (a barrier between them fixes it), a write over what another may still be reading E-COOP-REUSE, an index read from data or differing by a run-time value beside a write E-COOP-UNDECIDED. An array from outside: each element written by one thread of one block, at an index like b * 256 + t or (bx * 32 + r) * h + by * 32 + tx, and read only by the thread that writes it (E-COOP-GLOBAL); guard a single writer with if t == 0. A closure in the body names no shared array, pipeline or outside array (E-COOP-UNDECIDED).

shuffle(v, lane), shuffle_xor(v, mask), shuffle_down(v, delta), shuffle_up(v, delta) and let s = reduce + warp yield v; (reduce's operators, a fixed butterfly order) need whole warps: only under conditions warps agree on, t < 32, t / 32 == w, ty < 4 when tx counts 32 (E-COOP-WARP); so do the votes, one instruction each: warp_ballot(c) (u32, bit l for lane l), warp_any(c), warp_all(c), the same in every thread of the warp, and warp_match(v) (the lanes whose v has this lane's bits; 32- and 64-bit integers and floats). A thread obeys the lane rules: no outer scalar writes, I/O or nested regions.

pipeline p:u64[256] depth 2; declares 2 stages of 256 u64 (u32 i32 f32 u64 i64 f64) in the block's shared memory. p.fill(x, start, count) starts copying x[start..start+count] into the next free stage, zeros past count; p.wait() is a barrier after which the oldest stage in flight reads as p[i]; p.release() ends its readers, and the next barrier frees the stage. All three need the whole block (E-COOP-BARRIER). Reading, releasing or waiting with no stage in the needed state is E-STAGE-UNREADY; a fill with no free stage, or a wait while a stage is still readable, is E-STAGE-BUSY (put a barrier after release before the next fill); a loop or if that leaves a pipeline in another state than it found it is E-STAGE-LOOP: fill depth - 1 stages first, then fill, wait, read, release, barrier each iteration, with no break or continue. Any use of p but as the receiver of its operations reads the readable stage; fill copies from an outside array where the region runs (E-PLACEMENT). Depth changes shared bytes and how many copies a wait leaves in flight, nothing else. When a block cannot say the kernel you want, keep that kernel: write it in CUDA as a foreign implementation of the function (the foreign card), which cairn foreign inspects and cairn validate holds to the reference, rather than a narrower one.
```
