# Changelog

## Unreleased

- **Hardening (fifth review)**: the project loader now reads every manifest of a build with one checker, so a dependency's `cairn.toml` is refused for the unknown table, unknown option, bad name or unknown kind, architecture or target that the root's would be, and its paths must be canonical (no `.` segment) and inside its own root, contract files included. A name and a directory each pin one project of the build, so a second name for one directory is an error rather than a skipped diamond, and no dependency may take another's name or the root's. A module belongs to one project: no project source may declare a `std.*` module, no project may reopen a module another declared, and a source with no `module` header may no longer continue the module a dependency left open. An executable's `main` is searched only in the root project's own sources. `--incremental` now writes each object's sha256 beside it and reuses the object only while its bytes still match, so a truncated, half-written or substituted object is compiled again instead of linked (an integrity check against interrupted or shared caches, not against anyone who can write into `build/`); `build/objects`, an object and its digest are refused as symbolic links; and a unit compile that times out or is killed produces the same `cairn.build/1` record as a whole-program build and leaves no object under its key.
- **Generics**: bounds may now promise a kind (`[T:copy]`, `[T:affine]`) or a closed scalar class (`integer unsigned signed float numeric scalar`) as well as traits, on functions and on generic records, and are checked at the call (`E-BOUND`). `cairn check --generics` checks each template once against its bounds, at opaque witnesses that are as owning as the bounds allow or at every type of a scalar class; every template of `std` now certifies, so misuse of a container is reported in the caller's terms. Unbounded templates are still accepted per instance.
- **Editor**: `cairn lsp` now answers completion (fields and methods after `name.`, enum variants, a module's public names through its alias, locals with their types, visible declarations, builtins, types and words; modules after `import `, recipes after `derive `, traits/kinds/classes inside a bound), signature help with the active parameter (method syntax counts the receiver), document-wide references and rename where one document can prove the answer sound, and go to definition into the packaged `std` sources; hovering a callee adds its signature and effect row. Because a buffer being typed rarely compiles, every feature reads its context from the current tokens and its meaning from the last analysis that succeeded, matched by name, so completion keeps working mid-expression — including for a binding typed after that analysis.
- **Constants**: a `const` folds exact arithmetic, comparison, logic and conversions over literals and other constants (in any order of declaration), and may name a static extent in a signature. It used to be one literal, which excluded even `-5`.
- **Operand order**: two calls that can be observed from outside (I/O, machine access, atomics and locks, function values) may no longer sit side by side in one expression, where C++ would choose which runs first; the audit is now one footprint per nested call.
- **Dependencies**: `[dependencies] name = "deps/name"` vendors a project inside the root: modules only, `pub` only, loaded before the project's own sources, pinned by hash in the receipt; nothing is fetched and nothing outside the root is read.
- **Derivable implementations**: a recipe may generate trait `impl`s; `std.derived` offers `derive eq`, `derive ord` and `derive hash` for records, and a generic impl now applies exactly where its bounds hold, so `std.core` implements its traits once per scalar class (`impl[T:integer] Ord for T`) and covers every integer type.
- **Tour**: `docs/tour.md`, twelve complete programs from checked arithmetic to recipes and the foreign boundary; the suite builds and runs each under sanitizers, so the tour cannot rot.
- **`cairn doc`**: an API reference generated from the checked program (signatures, bounds, comments, inferred effect rows; a template's row is the one at its witnesses). `docs/std_api.md` is its output for the packaged library and a test keeps it current.
- **Fifth review (checker)**: an adversarial pass over everything above found, and this release fixes and pins: a part's extent expression was emitted twice, so `first(c.fetch_sub(1, ..), b[2..4])` passed its guard with one value and gave the callee another (an out-of-bounds read and write under both compilers); a part's bounds and extent are now names, literals and arithmetic (`E-CALL-SHAPE`, the rule a computed capacity already followed), and a host `reduce` reads its extent once. A `linear` value could be boxed into `Dyn[Trait]` and dropped unconsumed. `cairn check --generics` said `ok` for a template whose `pure` ceiling or lane depended on what an implementation's member does: certification now applies the whole-program rules at its witnesses, a ceiling declared on a trait's member binds every implementation and is what a bound promises (`std.core` declares `less`, `same` and `hash` pure), and a member without one shows as `bound:Trait.member` in a template's row. An `f32` constant folded in double precision and rounded once at the end, so it could differ from the same expression at run time (and leak into an integer constant used as an extent); every literal, conversion and operation now rounds as the machine will. A name written in a recipe resolved in the *deriving* module, so its `helper` or `trait Same` captured the recipe's: expansion is hygienic now, and only `$` splices belong to the deriving module. An observable call could sit beside an element access or checked arithmetic whose abort C++ may order before or after it. A constant natural was refused as a type argument (`Array[u64, N]`, `scale[N](x)`). Two `impl` blocks for one type were merged into one implementation, a generic impl whose bound asks the question it answers silently lost to a concrete one, and `impl NotATrait for S` crashed the checker.
- **Taking a record apart**: `let Conn(sock, sent) = c;` consumes a record value and binds every field, the dual of constructing it. An owner or a linear value kept inside a record finally has a way out that leaves no zeroed shell (the std guide listed that as a sharp edge); only the declaring module takes a `linear` record apart, so a protocol cannot be ended from outside.
- **Recipes take function names**: `recipe fieldwise[F:fn] for R` with `derive fieldwise[half] for P;` splices the name as the deriving module wrote it, so one generic function serves fields of different types; this is the practical part of "recipes over expression fragments". Found on the way: a generic call typed its arguments in the *template's* module, so `m.twice(p.a)` was `E-PRIVATE` when `p` was the caller's private record and the caller's own type parameters were unknown there; arguments are now typed where they are written. `T(x)` converts or constructs at the instance's `T`, which a class-bounded template needs to compute a mean.
- **Second user**: a columnar analytics engine written against 1.1 (`examples/apps/analytics`) found one compiler crash and a list of rough edges, all addressed: a generic callee given a part of a record's field (`sort(n, c.price[0..n])`) now takes the element type from the field; a recipe `fold` takes any function of two operands (`fold add_wrap each ...`), a `where` may fold statically (`where width = fold + each f in R { bytes(f) }`, with `min`/`max`), an `each` may splice several expressions per step, and a recipe may generate a `kernel fn`; `len("text")` is the literal's length and identifies an extent; a `@pinned` or `@unified` view is lent where a `@host` view is asked for (and `@unified` where `@device` is), so host helpers serve staging buffers; the placement words `host device pinned unified` are words only after `@` and are no longer reserved; a part written outside an argument list is `E-VIEW-ALIAS` instead of an internal error; a generated record with a repeated field is reported at its `derive`; `>>`, `reduce +` on a signed column and a placement mismatch each say what to write instead; and `cairn fmt` lays out `each { }` splices and `fold` as brackets rather than blocks. Bounds are written `[T:Ord]` everywhere, as the formatter writes them. `cairn expand` prints what the derivations generated, as source; a manifest is named by its path, so one tree may hold a second configuration (`cairn run app/gpu.toml`); and a `--generics` verdict names the parameters that promised no kind.
- **Proof**: the Lean ownership calculus now has the places the language has, not just whole owners. A place is a whole owner, its header (`len`), its elements (`d[]`) or a part `d[lo..hi]` whose bounds are literals or immutable names; the checker decides disjointness syntactically as `checking.py:overlaps` does, chaining the `lo <= hi` facts of the parts in play, while the machine evaluates the bounds under an arbitrary valuation and traps -- a defined abort, not a fault -- when a slice is formed backwards. An accepted program has no reachable race for **every** valuation, and the invariant that makes the chain sound, "every fact in play belongs to a slice whose guard has already run", is explicit (`TasksGuarded`, `ovl_sound`). Progress is proved (`accepted_progress`), replacing the `OpenGoal.Progress` that was left open. New witnesses: two parts that really overlap drive the machine to a race, and the accepted `d[6..3]` program that orders two overlapping parts reaches the trap instead.
- **Application**: `examples/apps/analytics`, a columnar query engine over a million wire-encoded rows, written as the second user of the 1.1 features. Its table types, per-column statistics, unrolled column kernels and device reductions are generated by four recipes of its own (`each` at declaration, statement, field-list and call-argument level, `where`, `fold`, `require` domains, `$` splices, a recipe calling its own module's public helper by full path), derived for a record of its own module and for one of another. It ingests with `derive wire` codecs and `std.io`, answers every query twice — row-wise against column-wise, `compact` against a loop, `reduce +` against `reduce add_wrap`, one pass against a four-way task split, a `T: Aggregator` bound against `Dyn[Aggregator]` — and returns 0 only when the answers agree. A second manifest, `gpu.toml`, swaps the entry point for one that repeats the aggregates on the device, including a queued `spawn transfer` / `spawn parallel ... after` / `wait` pipeline, and requires the results to be equal bit for bit. `tests/test_app_analytics.py` builds it under both compilers, under Address and UndefinedBehavior sanitizers and with `--incremental` (a body-only edit recompiles one unit), and skips the device half where there is no GPU.
- **Application, second pass**: `examples/apps/analytics` is rewritten against the features above and keeps no workaround. Its comparisons and its three `Aggregator` implementations are now generated (`derive eq`, `derive ord`, and its own `recipe folded[F:fn]`, applied to `add_wrap`, `max` and a function of its own); the summary record is laid out column by column by an `each` that splices three fields per step; the unrolled kernels join their accumulators with `fold add_wrap`; the device half is `module analytics.device` (`src/device.cairn`, `src/device_main.cairn` in `gpu.toml`), so its functions drop the `_device` suffix; its pinned staging is filled and read back by `std.mem` and `query.wrapping_total` instead of by hand; a report label is `ro<u8>[LABEL]`, so the compiler counts it; and `cairn check --generics` now exits 0 for the project, all seven of its templates certifying against `[T:copy]`, `[T:affine]` and `[T:Ord + affine]`.
- **Source equivalence over memory**: the SMT model now takes array views. A view parameter is an SMT array per component of its element with the extent its signature names, indexed under the `cr::at` guard; `len` reads that extent; `x[lo..hi]` shifts the window under the `cr::part` guard; `rw` single borrows, `buffer`/`Buf` scratch local to a function, `compact`, host `reduce` and `void` results are modeled too. What a call observes is now its result **together with the final contents of every `rw` parameter**, element by element over the whole extent, and the admitted inputs are the ones the emitted entry guards admit (`cr::view`, and `cr::disjoint` between an `rw` view and every other view), so read-only views may alias while `rw` storage is distinct. A pass over a symbolic extent is unrolled under the same sixteen-iteration budget, so it needs a precondition that bounds the extent; a literal extent needs none. An owner that moves (`take`, `swap`, a returned or stored owner), a tag inside a view, two views of one array in one call, a float reduction's unspecified order, device placement, lanes and tasks stay unknown with a precise reason. Counterexamples carry the storage that separates the two functions and are replayed through the concrete evaluator, and `tests/test_semantics.py` runs the solver's counterexamples and random inputs against the native binary, comparing results, final `rw` contents and `SIGABRT` traps.
- **Host lane pool**: a host `parallel` statement no longer creates and joins its own threads. The first host region of a process creates the lanes and every later one reuses them; the count comes from the machine, or from `CAIRN_LANES` when that names a count from 1 to 1024 (anything else traps). A region below sixteen thousand elements is compiled as the loop it replaces and starts nothing; above that it engages one lane per eight thousand elements, up to the pool's size, so a small region never wakes sixty-four threads. Both numbers were chosen by measurement. The thread that starts a region is always one of its lanes and can finish it alone, so a lane that blocks on a task, regions started at once from several tasks, and an exit while workers are idle all make progress rather than deadlocking; the pool is never destroyed, and an exit handler joins its threads. Nothing about the language changed: `run(n, body)` still runs every index exactly once and returns when all of them have, and which lane runs which index was never observable. On a 64-core GH200 the size at which a host region starts to beat the sequential loop fell from about ten million cheap elements to about a hundred thousand, and from three million to thirty thousand for a body costing about a nanosecond an element; a thousand small regions in a loop cost 1.3 ms each before and now cost what the loop costs (`evidence/v1_2/host_regions`, one machine, both compilers, no tuned baseline).

## 1.1.0

- **Recipes**: generators are library code. `recipe name[K:nat] for R { ... }` holds ordinary function and record declarations with static `each` (over a record's fields or a natural range, at declaration, statement, field-list and call-argument level), `fold`, `where` values, `$name` splices and `require` domains; `derive name[naturals] for Type;` expands it before checking into code of the deriving module. The closed Python generator behind `derive wire` is gone: `std.wire` is twelve lines of CAIRN and produces the same C++ byte for byte. Receipts pin each recipe by the hash of its tokens. `wire` is no longer a reserved word.
- **Queued device work**: `let t = spawn transfer(dst, src);` and `let k = spawn parallel i in n after t { ... };` put device work on its own stream and return; the ticket leases what the work touches until `wait`, `after` orders work by device events without a host wait, and work queued after a ticket may share what that ticket holds. This exposes the runtime's stream tickets, which until now only its own tests used.
- **Incremental builds**: `cairn build --incremental` compiles one object per module against a shared interface header and reuses an object only when everything that went into it hashes the same; a body-only edit recompiles one module. Opt-in, because it gives up inlining across modules; device programs and images stay one unit.
- **Checked reduction**: `reduce +` is offered on unsigned integers, on the host and on the device, and traps exactly when the total does not fit, in any order.
- **Evidence**: a preregistered fresh-model pilot (`evidence/v1_1/ai_pilot`): nine of nine tasks solved from the rule cards alone, eight on the first compile, every transcript audited. The cards were then revised with what the subjects had to guess.
- **Source equivalence**: the SMT model now covers records, tag-only enums and payload sums with `match` and `try`, IEEE `f32`/`f64` under the compiler's strict floating contract, fixed local storage (`stack x:T[N]`, `Array[T, N]`) with its bounds guard, and `for`/`while` with `break`/`continue` unrolled within a sixteen-iteration budget. A value is compared component by component, a sum by its tag and active payload only, and inputs are quantified over well-formed tags. Exceeding the unrolling budget is a residual obligation the solver must refute, and a returned NaN — whose payload bits the theory's single NaN cannot speak about — is reported unknown rather than equal. Heap owners, view parameters, `rw` borrows, recursion, concurrency and void results stay unsupported with a precise reason.

## 1.0.0

The language grows from a checked CPU kernel language into a general systems language; the compiler core was rebuilt around one typed tree, and every addition arrived with native behavior tests, rejection tests and an application.

- **Types**: generic records, sums and functions with inference and on-demand monomorphization; payloads and fields of any value type; inline `Array[T, N]`; `i8`/`i16`; hex, character and string literals; `const`; layout attributes.
- **Traits**: static dispatch on `Self`, bounds checked per instance, `value.method(...)` resolved in the receiver's module, explicit `ro<dyn Trait>` fat references with a `dispatch` effect, and owned `Dyn[Trait]` values for heterogeneous collections.
- **Ownership**: second-class borrows of values and arrays, checked array parts with visibly-disjoint splitting, first-class zeroed `Buf[T]`, affine moves, `take`/`swap`, `linear struct`, `defer`. No lifetime annotations exist.
- **Errors**: `try` propagates the failure of a two-variant sum; it is the only propagation form.
- **Functions**: copyable code pointers and non-escaping closures passed as `ro<fn(...)>`.
- **Conversions**: float-to-integer is a checked truncation that traps on NaN or out of range (it was unsupported).
- **Effects**: checked `pure`/`effects(...)` ceilings; `extern` declarations (optionally `extern "symbol"`) with mandatory effects, `ffi:symbol` propagation and an `unsafe` gate; `mmio_read`, `mmio_write`, `asm`.
- **Concurrency**: `spawn`/`wait` with linear scope-bound tickets and borrow leases; `Atomic[T]` with explicit memory orders; `Mutex[T]` entered only through a closure. ThreadSanitizer-clean.
- **Audit**: an adversarial review of the new checker found fourteen accepted-but-unsound programs (use after free, overflow through extent identity, three lease races, forged linear values, under-reported effects, operand-order holes); each is fixed and pinned in `tests/test_soundness.py`, and the first library author's seven compiler bugs are pinned in `tests/test_language.py`. A second round with three reviewers (checker, trait and module system, emitter) found about forty more: closures that freed or raced what their own call lent, lanes whose own bodies escaped the rule their callees obey, a device collector that was never checked as device code, impls never held to their trait, overlapping and ambiguous impls, a self-owning record classified as a copy, `try` abandoning an owner mid-expression, `len` and `transfer` ignoring task leases, privacy holes in `family` and `derive wire`, locals differing only by underscores sharing a C++ name, executables that dropped reachable vtable members, and a `.gitignore` pattern that had hidden `std/core.cairn` from every fresh checkout. A third pass attacked only the new rules and found nine more (a host view reaching device code through a helper, an internal error from an unmapped lane footprint, a `Self`-returning member behind `dyn`, a record holding itself through an inline array, and lanes that could not yet reach helpers that dispatch). All are fixed and pinned there too; the fixes also made the rules more precise (a closure borrows exactly what it captures, a parallel map may take a closure that writes nothing it captured, K-way part splits are accepted).
- **Data parallelism**: `parallel i in n` lanes that are race free by construction, `kernel fn` device helpers, `reduce`, placement types (`@host @pinned @unified @device`), scoped device owners, `transfer`, and the bounded collector as stable stream compaction on the device. One lane body lowers to host threads or CUDA lanes; guards work in device code and abort the host.
- **Modules**: `module`, `import` (aliases and name lists), `pub`, and a standard library written in CAIRN and linked from the package.
- **Targets**: Linux x86-64 and AArch64 hosts from one toolchain table, CUDA through `nvcc` under the same strict floating-point contract, and a freestanding AArch64 profile verified under QEMU.
- **Proof**: a dependency-free Lean 4 development proves the certificate checker sound, checks the seventeen collector certificates, and proves in-bounds stores and stable selection for the collector loop model; receipts report it only for the exact checked bundle.
- **Agent layer**: the canonical projection, edit sessions, effect ceilings and rule cards cover the whole language; an edit cannot add a lane race, a shared write, an allocation or a task past its ceiling.
- **Tooling**: `cairn fmt` (comment preserving), `cairn lsp`, an editor grammar, optional `#line` source maps, `ruff` formatting and lint for the Python sources, `make lint`.
- **Compatibility**: every 0.6 program, diagnostic code and receipt field is preserved. Newly reserved words: `trait impl dyn const pub linear parallel reduce spawn try as type device pinned unified`. New builtin names (`take swap transfer wait mmio_read mmio_write asm`) yield to a program's own function of the same name. Two 0.6 rejections became legal by design: record payloads in sums and arrays of sums.

## 0.6.0

- Added zeroed lexical heap buffers and fixed stack arrays with nonescaping borrows, explicit storage/effects, and metadata-only len.
- Added monomorphic scalar payload sums, typed error data, exhaustive match, and correct loop break/continue through match arms.
- Added exact integer coefficient certificates for 17 collector arithmetic obligations; trusted Python checker, not Lean.
- Added all-function scalar equivalence coverage and public-type census; unsupported entries block aggregate verification.
- Replaced substring feature selection with lexical cards and shortened common instructions without altering edit authority.
- Fixed finite-task acceptance after abnormal child exit; added address-space limits to CLI execution.
- Added independent decimal/sorting/filtering examples, lifetime observer tests, production sanitizer and abort tests.
- Retained local-only publication policy and explicit gaps in C++ breadth, native proof, GPU support and measured AI proficiency.

## 0.5.0

- Split native syntax, typed expansion, checking, C++ emission and runtime into an installable src/cairn package; retained one implementation behind the compatibility facade.
- Added one CLI for creating, checking, building, running, testing, inspecting and scalar-comparing programs.
- Added explicit ordered multi-file projects, source-origin diagnostics, data-only manifests and native executable entry points.
- Added expression-bodied functions, optional host placement in the CPU profile, and else-if desugaring. Existing arithmetic and safety rules are unchanged.
- Preserved expression/body edit support and source comments for the compact forms.
- Changed the new CLI's default architecture to baseline x86-64; legacy comparison harnesses keep their explicit x86-64-v3 profile.
- Added offline wheel packaging, clean-install tests, fresh build directories, input-path rejection tests, and a private-only first-publication tool.
- Corrected source-audit density accounting to include the complete split package, not merely its small facade.
- Organized earlier specifications and teaching data separately from active compiler code. No model training, new Lean verification, GPU lowering or timing improvement is claimed.
