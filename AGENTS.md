# Working on CAIRN

Read README.md, docs/language.md and docs/architecture.md. Start with `python3 bin/cairn doctor`, `make lint` and `python3 -m pytest -q tests -n auto`. Use the existing Python API and real CAIRN source; do not invent unsupported libraries or syntax.

**Ownership of the code.** The parser owns syntax and source ranges; `modules.py` links packaged `std` modules; expansion owns the closed generators; checking owns names, types, generic instances, places, ownership, leases, lanes, placement and effects, and never produces text; codegen lowers the typed tree; the runtime headers own guards, owners, threads and device calls; `toolchain.py` owns every native flag. Project manifests are data, never build scripts. Keep changes small and in the owning file. The formatter owns layout (`ruff format`, 120 columns; `cairn fmt` for `.cairn`); the smallest clear program wins, but never by hiding a cost or deleting a check.

**Do not weaken** a task, reference, input domain, numerical policy, alias rule, lease, lane rule, effect ceiling or test to make a candidate pass. Checked and wrapping arithmetic differ. Borrows are second class: if a design needs a stored or returned borrow, it needs an owner, an index or a handle instead. An owner moves; `take` and `swap` are the only ways out of a place. A linear value is consumed exactly once on every path. A lane touches only element `[i]` of what any lane writes. While a ticket is live its borrows are leased. `unsafe` is for the foreign boundary and the machine, never for silencing the checker.

**Keep claims distinct**: accepted, typed, native-built, finite-tested, sanitizer-clean, SMT-equivalent, Lean-checked and benchmarked are different statements, and unknown is never success. The Lean result covers the certificate checker, the seventeen collector certificates and the collector loop model only; the receipt turns it off when the bundle changes, so regenerate with `tools/export_lean_certificates.py` and rebuild `proofs/` when you touch a rule. Do not claim a speedup, GPU advantage or AI proficiency without executed evidence recorded under `evidence/`.

**Every language change needs** a precise elaboration, a failure policy, a cost boundary (which effects it adds), a rejection test, an independent behavior test run natively under both compilers (and the relevant sanitizer: address/leak for ownership, thread for concurrency, the device death tests for guards in lanes), a rule card in `teaching.py` selected from lexical tokens, an entry in `docs/language.md` and in `docs/capabilities.json`, and the canonical projection must still round-trip to identical native code. Count whole compiler dependencies in density measurements, not just a facade.

**Never** commit credentials, binaries, build trees or unrelated user files. Never change repository visibility, force-push, delete remote resources, install a token or publish from a test. Publication tests use fakes; the private publisher is opt-in and creates only a new personal repository. A task whose child exits abnormally has failed, even if it printed a pass.
