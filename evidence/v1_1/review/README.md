# An adversarial review of what landed after 1.0.0

On 2026-09-24 one reviewer tried to break what landed on main after `93dadac` (1.0.0), and what landed while the review ran, assuming each change had a bug its author did not look for. [SECURITY.md](../../../SECURITY.md) defines a soundness bug. The attacks were CAIRN programs, requests and records, checked by the compiler of main from `2b0adb5` onward and rebased as work landed. Accepted programs that ran were built with the project's own command line and the runtime headers, under clang++ 21.1.8 and g++ 13.3.0, with AddressSanitizer and UndefinedBehaviorSanitizer or ThreadSanitizer where a test says so. Z3 was 4.8.12, Python 3.12.3, on one x86-64 machine under WSL2, shared with four other agents at a load average between 100 and 350 on 16 cores. nvcc 13.2 compiled nothing for this review, and nothing ran on a GPU.

`tests/soundness/test_review_agent_and_device_layer.py` keeps every fix's regression test, and kept one open defect as a strict expected failure until the fix for #60.

## What was found and fixed

Eight defects were found and fixed, each in the file that owns the rule, each with a test that failed before its fix. One let a check that reports every refusal imply a verdict it had not reached, one ended such a check on a crash it then hid, one let a function skip its waits, three had a hint, a card or a record state something false, one priced code that cannot be built, and one refused a correct kernel.

| defect | what went wrong | fix |
|---|---|---|
| A check that reports every refusal judged a row an implementation had not joined | a reference's row joins its implementations' only once the implementation rules run, which such a check never reaches; beside an unrelated refusal, a caller whose ceiling only the implementation exceeds was reported neither refused nor under `not_judged`, so the record implied a verdict it had not reached | `compiler/refusals.py` leaves a reference with implementations, and whatever reaches it, unjudged (`6e75cbf`) |
| A call through a function value ended that check on a `KeyError` | a function whose address is taken, and which calls a refused body, gets no verdict, but a caller making an indirect call stayed judged; the fixed point read the missing row, the check ended on a fault, every later refusal was lost and the fault was kept only in `abandoned`, which nothing prints | `compiler/refusals.py` leaves unjudged an indirect call that may reach any function without a verdict, to a fixed point (`5b49047`); found by the composition differential below |
| A host atomic in a selected implementation let callers skip their waits | `6224ae4` let a device lane's atomic update keep the one wait and the `cq_NAME` entry by walking the bodies a call names, never the implementation a plan runs in the reference's place; a function whose implementation bumps a caller's `Atomic` on the host was held to one wait | `compiler/execution.py` walks each implementation of a reference as well (`38fc27e`) |
| `cairn predict` priced code its build refuses | a program whose selected implementation `needs(tma)` was priced on the A100, L40S and RTX 4090 cards for `sm_80` and `sm_89`, where a build is `E-IMPL-TARGET` | `perf/report.py` holds the target to the program as `projects/build.py` does; `--card all` lists such a card as refused (`97ab287`) |
| The fix for a type mismatch said a float conversion traps | `f32(1e300)` is infinity and `f64(2^53 + 1)` rounds, but the hint said every conversion "traps outside f32's range", telling an agent a rounding conversion was checked | `agent/diagnostics.py` says a float conversion rounds and is not range checked (`db5f855`) |
| The parallel card left out what keeps a function waiting | the card named transfers, device allocation, tickets, I/O, foreign calls and `@unified` views, not atomics, locks, function values, machine registers or host assembly, which `compiler/execution.py` also refuses | `agent/teaching.py` names them all (`0abf086`) |
| A validation asked to emulate a host program said it had | `cairn validate --emulate` of a program with no device code recorded `target: {kind: device, emulated: true}` beside `evidence: finite-tested` and no `emulation` record | `verify/validation.py` records the host target when nothing was emulated (`d53b065`) |
| A fully written shared table was refused at a data index | `lut[t] = table[t]; barrier;` writes every element, yet `lut[usize(x[i] % 32)]` was `E-COOP-UNWRITTEN` because the index could not be followed, which pushed a lookup table to `= zeroed` and a fill it does not need | `compiler/written.py` accepts an index it cannot follow once every element was written; the kernel runs on host threads under both compilers with the pattern fill, and clean under ThreadSanitizer (`a0361bf`) |

The fix to `written.py` changed one case of `tests/soundness/test_written.py`, which had held the narrower rule as intended: its array is now written everywhere but one element, so the refusal it names still holds.

## What is left open

`cairn tune` chooses an implementation on a validation made under any policy. `total_zero`, which returns 0, validated with the domain narrowed to `n = 0`: the finite cases passed, Z3 answered `smt-equivalent` under that assumption, the history kept the record as `finite-tested`, and `cairn tune --symbol total --at n=1e6` chose `plan total use total_zero;`, which `--write` would write. The history's contract digests the tolerance, the domain and the test policy, but `tune.validations` asks `History.validations`, which holds a record under any contract. A validation opened through `cairn mcp` takes its policy from the client when the project keeps no regressions file, so an agent can make this happen. The test was a strict expected failure; which contract a search should require was a decision for `perf/tune.py`'s owner, and nothing here changed it. Since fixed (#60): `cairn tune` chooses only on a validation at least as strict as the reference's pinned policy, and the test passes.

`cairn tune` also does not hold a candidate's implementation to the device target. For the program above whose selected implementation `needs(tma)`, `cairn tune --card a100` prices `plan scale use scale_bulk;` for `sm_80`, where a build is `E-IMPL-TARGET`; it chose the reference there only because the implementation had no validation. `cairn predict` now refuses such a target, and the same check belongs in the search's candidates (`perf/tune.py`).

Two more observations are stated, not changed. A check that reports every refusal keeps a fault after the first refusal in `Diagnostic.abandoned`, which no command prints, so a compiler crash there reads as `not_judged`; the `KeyError` above was invisible until a differential looked for it. And `cairn test --emulate` carries `emulation` inside `blocks` and in each replayed regression, not at the top of its record.

## The Z3 test that failed under load

`tests/verification/test_semantics_native.py::test_the_model_agrees_with_the_machine` asks Z3 for a counterexample on fourteen perturbed pairs at a 20 s wall-clock limit. Timed one at a time here, thirteen take 0.07 to 2.8 s, and `narrow` (`f32(x) / f32(y)` against `f32(x / y)`) takes 9.3 to 10.3 s of CPU and 10 to 16.5 s of wall time at a load average of 175 to 200. The SMT translator is unchanged since 1.0.0 apart from the file list of `implementation_hash()`, so the failure is load, not a regression. The test now asks once more at the solver's 30 s ceiling when Z3's record of a query says it timed out, and names a pair that times out twice in a skip after every other case has run. Any other `unknown` still fails, and a timeout is never read as a counterexample or a pass (`ab1f333`). Both paths were driven by substituting the solver's answer.

## What this review did not attack

A review finds what its author thought to try, and one reviewer wrote every attack here, on one machine. Nothing ran on a device, so the device lowering of atomics, wide accesses, unzeroed shared arrays, the finish and the enqueued entry is compiled or emulated only. The benchmark harness adapters (`projects/harness*.py`), the search's lazy candidates and objective (`perf/objective.py`, `perf/search.py`), the `cairn state` and investigation records, the value model and the Lean calculus were read at most and not attacked. The composition differential is a script run for this review, not a tool of the repository; its two findings are pinned by the regression tests above.
